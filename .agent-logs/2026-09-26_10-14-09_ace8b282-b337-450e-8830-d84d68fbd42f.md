I have a working AI meeting-notes app (Next.js + Postgres) called Minutes. It
currently has two pages: Meetings (reverse-chronological list of recordings)
and Calendar (real Google Calendar OAuth, read-only, with an attach-recording
flow). The meeting detail page has Summary, Ask AI, Transcript, Action items
and Highlights tabs, all backed by real data. There is no auth and no user
accounts: it is a single-workspace app.

I want to add a third top-level page and make it the landing page: "Open items".

WHY (keep this in mind when making judgement calls): the current landing page
is an archive of recordings. Nobody opens a meeting-notes tool wanting a list
of meetings. They open it because they forgot what was promised, or they need
to know what someone else owes them. The app should answer that on arrival.

WHAT TO BUILD

1. Route /open-items, and make it the default landing page. Nav order becomes
   Open items, Meetings, Calendar. Meetings stays exactly as it is.

2. Two tabs at the top of the page: Pending and Done. Pending is the default.
   Pending lists every action item not yet completed; Done lists completed
   ones, most recently completed first, so nothing disappears.

3. Items are grouped by the person who owns them, using the speaker name from
   the transcript. Groups are ordered by most open items first. Each group
   header shows the speaker's avatar initials, their name, and the open count.
   Items with no identifiable owner go in a final "Unassigned" group.

4. Each item row shows:
   - a checkbox to mark it done
   - the item text
   - a due-date chip ONLY if a due date was extracted; overdue styling if past
   - a timestamp chip (e.g. "6:41") that links to the meeting detail page and
     deep-links the transcript to that moment
   - the meeting title and date

5. Clicking a row expands it inline to show the transcript utterance where the
   commitment was made: speaker avatar, speaker name, timestamp, and the quote.
   Only one row expanded at a time.

6. Empty states for both tabs. Pending with nothing open should say so plainly
   and link to Meetings.

DATA WORK

- Check the action_items table. It needs a completed boolean (default false)
  and a completed_at timestamp. Write a migration if they are missing.
- Each action item must reference the transcript segment it came from, so the
  quote and the timestamp are real, not derived on the client. If that link
  doesn't exist yet, add a column referencing the transcript segment id and
  backfill it during extraction.
- Owner: use whatever speaker attribution already exists on action items. If
  items are not attributed to a speaker today, extend the extraction prompt to
  assign an owner from the meeting's speaker list, and fall back to Unassigned
  rather than guessing.
- Speaker names are editable in this app (the Suggest names flow), so the
  grouping must read the current speaker record, not a name copied onto the
  action item at extraction time. Renaming a speaker should regroup the page.
- Due dates: only if the extraction already produces them, or can be made to
  reliably ("before Friday" -> a date relative to the meeting date). If that is
  unreliable, skip due dates entirely and drop the overdue chip. Do not fake it.

API

- GET /api/open-items?status=pending|done returning items grouped by owner,
  each with its meeting, timestamp, transcript quote, due date and completed
  flag. One query, no N+1 per item.
- PATCH /api/action-items/:id to toggle completed. Optimistic update on the
  client, revert on failure.

CONSTRAINTS

  human specifically for whether the backend is real.
- Match the existing visual language: same nav, same card styling, same purple

- Use real semantic elements: <input type="checkbox"> with labels, <button>,
  <a href>. No click handlers on divs.
- Plural strings on this page must be correct ("1 item", "2 items").
