I'll walk through it with your own app, using one real question from start to finish.

## The problem RAG solves
Claude only knows what's in the prompt you send. It has never seen your meetings. So for any question you either:
- **send everything** (all transcripts), which is expensive and slow, and stops working once there are too many meetings, or
- **send only the relevant parts**. That's RAG: **find** the relevant parts first, then **give** them to Claude.

RAG has two phases: **indexing**, done once per meeting, and **answering**, done for every question.

---

## Phase 1: Indexing (once, when a meeting finishes processing)

### Step 1: Chunk
An hour-long transcript is too big to search as one block, so it's cut into small pieces of about 1,000 characters (`chunkLines` in `src/lib/rag/index.ts`):

```
Chunk 17:
Meeting: Overview & Scrutiny Panel (2026-09-10)
[24:02] Pete Barber: I'm worried about shutting St Mary's before the new site is ready.
[24:15] Speaker 4: Parents haven't been consulted properly either.
```
Each chunk overlaps the next by one line, so a conversation that crosses a boundary isn't cut in half.

### Step 2: Embed (turn meaning into numbers)
Each chunk goes to Voyage AI, which returns **1,024 numbers** called an *embedding*. Think of it as coordinates on a map of meaning:
- "shutting the school" → `[0.12, -0.83, 0.44, …]`
- "school closure" → `[0.13, -0.80, 0.41, …]` ← nearly the same numbers
- "budget for road repairs" → `[-0.67, 0.22, 0.91, …]` ← far away

**Text with similar meaning gets similar numbers, even when the words differ.** That's the key idea behind RAG.

### Step 3: Store
Each chunk is saved in the `transcript_chunks` table with two search-ready columns:
- `embedding`: the 1,024 numbers, stored with **pgvector**, the Postgres extension for vectors.
- `tsv`: a keyword index of the words, which is ordinary Postgres full-text search.

Indexing is finished. It never runs again for that meeting unless you click **Update notes**.

---

## Phase 2: Answering (every question)

Question: **"What concerns did councillors raise about the school closure?"**

### Step 4: Embed the question
The question goes through the same Voyage model and gets its own 1,024 numbers, which places it on the same map of meaning.

### Step 5: Search two ways at once (`retrieve()`)
- **Vector search:** "which chunks have numbers closest to the question's?" It finds Chunk 17, because "shutting St Mary's" is close in meaning to "school closure", even though the word "closure" never appears.
- **Keyword search:** "which chunks contain the words *concerns, councillors, school, closure*?" It finds chunks that use those exact words.

Why both: each one misses things the other finds.
- Vector search understands meaning but is bad at exact names and numbers ("Pete Barber", "£2.4m").
- Keyword search is great at exact words but misses synonyms ("shutting" vs "closure").

### Step 6: Merge the two lists (Reciprocal Rank Fusion)
Each search returns a ranked list. Each chunk gets points based on its position in each list, and the points are added up:

| Chunk | Vector rank | Keyword rank | Total score |
|---|---|---|---|
| 17 | 1st | 3rd | **highest** (ranked well in both) |
| 42 | 2nd | not found | medium |
| 8 | not found | 1st | medium |

Chunks that **both** methods like rise to the top. The top **12** are kept (`RAG_TOP_K`).

### Step 7: Re-read the lines
For those 12 chunks, the app reads the transcript lines again from the database, so renamed speakers show their current names (`renderExcerpts()`).

### Step 8: Build the prompt (`libraryContext()` in `src/lib/ask.ts`)
```
RULES: answer only from this material, cite [[meeting@time]], say if you don't know.

CATALOG: every meeting with its title, date, speakers and a short overview   ← always sent
EXCERPTS: the 12 retrieved passages                                         ← changes per question

QUESTION: What concerns did councillors raise about the school closure?
```
That's only a few thousand tokens instead of every transcript.

### Step 9: Claude answers
> Pete Barber worried about closing St Mary's before the new site is ready [[abc@24:02]], and others said parents weren't properly consulted [[abc@24:15]].

Claude can only cite what it was given, so every claim can be traced back to a moment in the recording.

---

## How the name breaks down
- **R**etrieval: steps 4–7, finding the relevant chunks.
- **A**ugmented: step 8, adding them to the prompt.
- **G**eneration: step 9, Claude writing the answer.

## Where each piece lives
| Step | File |
|---|---|
| Chunk, embed, store | `src/lib/rag/index.ts` → `indexMeeting()` |
| Voyage calls | `src/lib/rag/embeddings.ts` |
| Hybrid search and RRF | `src/lib/rag/index.ts` → `retrieve()` |
| Build prompt and answer | `src/lib/ask.ts` → `libraryContext()`, `streamAnswer()` |

## The one weakness to remember
