Yes. R2 is Cloudflare's object storage product, S3-compatible, so the same thing.

In the Cloudflare dashboard:

1. Go to **R2 Object Storage** in the sidebar. The first time, it asks for a card, but the free tier (10GB, no fees for downloads) won't charge it.
2. **Create bucket**, name it `fathom-clone`, and leave location on Automatic.
3. In the bucket, go to **Settings**:
   - **Public Development URL:** click Enable. The `https://pub-xxxx.r2.dev` address it gives you is `R2_PUBLIC_URL`.
   - **CORS Policy:** add this so browsers can upload straight to the bucket and play videos from it:
     ```json
     [
       {
         "AllowedOrigins": ["*"],
         "AllowedMethods": ["GET", "PUT", "HEAD"],
         "AllowedHeaders": ["*"],
         "ExposeHeaders": ["ETag"],
         "MaxAgeSeconds": 3600
       }
     ]
     ```
4. Back on the R2 overview page, go to **Manage API tokens** → **Create API token**:
   - **Permissions:** Object Read & Write
   - **Apply to:** only the `fathom-clone` bucket
   - Once created, copy the **Access Key ID** and **Secret Access Key**. The secret is shown only once.
5. Your **Account ID** is on the R2 overview page, and it's also part of the S3 endpoint address `https://<account_id>.r2.cloudflarestorage.com`.

Those values go into `.env.local`:
```
R2_ACCOUNT_ID=...
R2_ACCESS_KEY_ID=...
R2_SECRET_ACCESS_KEY=...
R2_BUCKET=fathom-clone
R2_PUBLIC_URL=https://pub-xxxx.r2.dev
```

The `r2.dev` address is rate-limited and meant for development, but that's fine for a demo. If it ever gets slow, you can connect a custom domain later.

With signed links you **don't need a bucket policy at all**. Delete it and leave the bucket policy empty. Access comes from the IAM user's permissions, not the bucket.

That error means the `Resource` doesn't match the actions. `s3:GetObject` and `s3:PutObject` act on **objects**, so the ARN has to end in `/*`:

- ❌ `arn:aws:s3:::my-bucket`: this is the bucket itself, and object actions don't apply to it, which causes your error
- ✅ `arn:aws:s3:::my-bucket/*`: this means every object inside the bucket

The same thing happens if the bucket name in the ARN has a typo, or if you pasted `YOUR-BUCKET-NAME` literally.

**Where the permissions go:** IAM → Users → `fathom-clone-app` → Permissions → Add permissions → Create inline policy → JSON tab. Paste this, replacing `my-bucket` with your exact bucket name:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject"],
      "Resource": "arn:aws:s3:::my-bucket/*"
    }
  ]
}
```

On the bucket itself:
- **Block all public access:** leave it ON
- **Bucket policy:** leave it empty
- **CORS:** yes, add the JSON from before
