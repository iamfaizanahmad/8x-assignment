  ### 2. Bugs found
  
  1. **High (cost abuse)**, `src/lib/pipeline/index.ts:96-107` and `api/meetings/[id]/summaries/[template]/route.ts:8-17`.
     - **Problem:** `getOrCreateSummary` never checks that the meeting exists or is `ready`. `GET /api/meetings/<any-random-id>/summaries/sales` builds an empty transcript, pays for a Claude call, and only then fails on the foreign-key insert (500).
     - **Consequence:** Anyone can loop this unauthenticated GET. A meeting that is still processing would also get an empty-transcript summary cached permanently.
     - **How I verified:** By reading the code. I did not run it, because that would spend money.
     - **Fix:** Load the meeting first; return 404 if it's missing and 409 if it isn't `ready` or the transcript is empty. Consider rate-limiting.
  
  2. **Medium (anyone can edit seed data)**, `api/meetings/[id]/regenerate/route.ts:10-18`, `api/segments/[segId]/route.ts`, `split/route.ts`, `api/speakers/[sid]/route.ts`, `api/highlights/[hid]/route.ts`, `api/action-items/[aid]/route.ts`.
     - **Problem:** Only DELETE checks for `source === "seed"`. Any visitor can reassign or split lines, rename speakers or delete highlights on the showcase meetings.
     - **Worse:** "Update notes" (shown after any reassign, `meeting-view.tsx:302-314`) runs a Claude call and **deletes every cached template** (`regenerate/route.ts:18`). That wipes the pre-generated summaries and brings live AI calls back for later viewers.
     - **Fix:** Reject edits and regenerate for seed meetings (return 403, and hide the controls). At minimum, block regenerate on seeds.
  
  3. **Medium (clip page leaks the summary)**, `src/app/share/[slug]/page.tsx:8-15`.
     - **Problem:** `generateMetadata` uses the General summary overview for the description of every link, including clips.
     - **Verified live:** `/share/7UULQTxBOVIG` (a clip) has `<meta name="description" content="Samantha and Daniel synced on the Acme onboarding launch…">`. The page body trims the data correctly.
     - **Fix:** Only set the description when `link.kind === "meeting"`. For clips, use something like "Clip mm:ss–mm:ss".
  
  4. **Medium (meeting stuck processing forever)**, `upload-dialog.tsx:59-65` and `meeting-view.tsx:36-52`.
     - **Problem:** The row is created before the S3 PUT. If the PUT fails, the tab closes, or the process POST fails (its response is ignored at line 64), the meeting stays `uploaded`.
     - **What users see:** The meeting page spins on "Uploaded" forever with no Retry (Retry only shows for `failed`). The list shows a "Transcribing" pill (`app/page.tsx:30-33`). The stuck row also counts toward the hourly upload cap.
     - **Fix:**
       - Check `res.ok` on the process POST.
       - Show Retry when status is `uploaded` and the row is older than about 1 minute.
       - Label the `uploaded` state correctly in the list.
  
  5. **Medium (cost guardrail order)**, `pipeline/index.ts:36-39`.
     - **Problem:** The 20-minute limit is enforced after Deepgram has transcribed, and been paid for, the whole file. The limit is also global 10/hour rather than 3/hour per IP.
     - **Fix:** Read the duration in the browser (media element metadata) and send it to `/api/uploads` for rejection there, or do a HEAD/probe first. Lower the cap or make it per IP.      - **Fix:** Make the index unique and use `onConflictDoNothing`, then re-select.
